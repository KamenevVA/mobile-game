# Монетизация, магазины и Yandex Mobile Ads (Unity / Android)

Дата проверки правил: 15 ноября 2026. Правила, доступность стран и банков меняются; перед подачей сборки повторно открыть ссылки ниже и проверить договор/выплаты в аккаунте. Это практическая карта, не юридическая или налоговая консультация.

## Что делать в первой версии

1. Сначала выпустить тестовый бесплатный Android билд без покупок, рекламы и аккаунта, проверить игру и удержание.
2. Для первого рекламного эксперимента подключить **один добровольный rewarded ad** (например, дополнительная ячейка после проигрыша) через тестовый блок Яндекса. Выдавать награду только по событию SDK `OnRewarded`, не просто по закрытию объявления.
3. Для США/Европы проверить доступность источника рекламного спроса и выплаты для вашего юридического лица/банка до планирования дохода. Яндекс SDK интегрируется глобально, но это не доказывает достаточный fill rate/CPM в западных странах. Позднее сравнить сети/медиацию, если аккаунты и платежи доступны законно.
4. Не проектировать уровни так, чтобы реклама или платная покупка была обязательна для прохождения. Не прерывать игрока interstitial во время решения пазла.

Реклама считает показы/аукцион и выплаты не превращаются мгновенно в деньги: нужна модерация, валидные данные плательщика, достижение порога и отсутствие hold. Пассивный доход/популярность не гарантируются.

## Площадки и применимость к команде из РФ

| Площадка | Публикация | Деньги и ограничения, важные для РФ | Роль на старте |

В любом магазине отдельно проверить требования к возрастному рейтингу, privacy policy, рекламе/трекингу, правам на контент, скриншотам и сборке. Если приложение направлено детям, правила рекламы/сбора данных существенно строже; для первой игры не выбирать детскую аудиторию как целевую без отдельной юридической проверки.

## Законный маршрут по выплатам

До выбора «зарубежной компании» ответить вместе с бухгалтером/юристом и банком:

1. Кто владеет игрой, IP, магазинным аккаунтом и рекламным аккаунтом — оба участника или компания?
2. Где реально находится и управляется компания? Кто подписывает договоры и платит налоги?
3. Поддерживает ли платформа именно этот country/account type и банковские реквизиты? Пройдёт ли реальную проверку бенефициара/адреса?
4. Как переводить доход законно и с учётом действующих экспортных/санкционных/валютных правил и налогового резидентства?
5. Какие договорённости у друзей по долям, авторству, расходам, доступу к репозиторию и выходу из проекта?

Не использовать номинальные адреса/чужой кабинет/чужой банк или VPN для маскировки страны. Несовпадение страны аккаунта, реального бенефициара и банковских документов может привести к блокировке и удержанию средств. Не записывать в `PROJECT_STATE.md` пароли, API keys, keystore, документы и банковские реквизиты.

## Яндекс: от регистрации до первого тестового rewarded в Unity

Инструкция для Android. Документация Яндекса на дату проверки сообщает версию Unity plugin 8.6.0 (6 октября 2026). При реализации выбрать последнюю совместимую версию из официальной документации/релизов и сохранить её номер в проекте; не брать старые копии из видео.

### А. Регистрация и рекламные блоки

1. Создать/использовать Яндекс ID, зарегистрироваться в [Рекламной сети Яндекса для мобильных приложений](https://partner.yandex.ru/apps).
2. Добавить приложение с тем же package/bundle ID, который будет в Android сборке; пройти проверку прав на приложение (контакты разработчика или `app-ads.txt`, если требуется для вашего случая).
3. Дождаться модерации. Пока приложение/блок не одобрены, не считать, что показы уже монетизируются.
4. Создать рекламное место формата **Rewarded** и сохранить настоящий ad unit ID в безопасном месте. Никогда не вставлять реальный ID в публичный репозиторий до контроля доступа; для ранней разработки держать dev ID в конфигурации, а не в исходниках.
5. Записать заявленные странам и пользователю правила приватности в privacy policy; определить корректную процедуру согласия и отказа.

### Б. Установка Unity и Android toolchain

1. Через Unity Hub установить поддерживаемую LTS версию Unity Editor.
2. При добавлении модулей включить **Android Build Support**, включая **Android SDK & NDK Tools** и **OpenJDK**.
3. Создать проект из **2D Core**. В Player Settings задать уникальный package name, portrait orientation, подходящую minimum API; для Play target — Android API 36 согласно текущему правилу Google. Проверить, что версия Unity/Android Gradle Plugin умеет target API 36.
4. Собрать пустое приложение на физический Android и проверить `adb devices`, прежде чем вмешивать ads SDK.

### В. Добавить официальный Yandex Mobile Ads Unity plugin

1. Открыть [официальный quick start](https://ads.yandex.com/helpcenter/ru/dev/unity/quick-start) и скачать официальный Unity plugin package; на дату документации это `yandex-mobileads-lite-8.6.0.unitypackage`.
2. В Unity: **Assets → Import Package → Custom Package…** выбрать файл и импортировать. Google External Dependency Manager поставить, если его ещё нет (не устанавливать дубликат).
3. **Assets → External Dependency Manager → Android Resolver → Resolve** (или включить auto resolve).
4. Unity **Player Settings → Publishing Settings → Build**: включить **Custom Main Gradle Template** и **Custom Gradle Properties Template**, как рекомендует Яндекс.
5. Сохранить исходную baseline сборку/commit и собрать снова. После добавления SDK проверить размер AAB/APK, ошибки Gradle, разрешения манифеста, startup time и кадры на X8b.
6. Скопировать официальный sample из репозитория плагина, добавить demo component и проверить на телефоне. В Editor объявления могут не загрузиться; фактическое SDK тестирование делать на Android.

### Г. Rewarded: поведение игры

По официальному Unity SDK 8 workflow:

1. Создать один `RewardedAdLoader` и использовать его для запросов.
2. Загрузить объявление вызовом `RewardedAdLoader.LoadAd(AdRequest)` (async/await или callbacks из sample для текущей версии).
3. Подписаться на loaded/failed/rewarded/closed/error callbacks до показа.
4. Вызвать `RewardedAd.Show()` только после нажатия игрока на кнопку с честным описанием награды.
5. **Выдать награду только в `OnRewarded`** и защищать выдачу от повторного callback/двойного вызова; закрытие/ошибка не дают награды. Сначала добавить награду в локальное состояние игры, отдельно сохранить progress.
6. Освободить ресурсы объявления/событий при завершении жизненного цикла согласно sample SDK 8.
7. При загрузочной ошибке не делать цикл бесконечных запросов; ограничить число retry и использовать backoff. Не блокировать кнопку или уровень, если реклама недоступна.

Пример бизнес-логики, не готовый компилируемый SDK код:

```text
if rewardedAdIsReady and playerPressedContinue:
    showRewardedAd()

onRewarded(reward):
    if thisAdHasNotGrantedReward:
        grantOneExtraBufferSlot()
        markRewardGrantedForThisAd()

onAdFailedOrClosedWithoutReward:
    keepPlayerProgressUnchanged()
    allowNormalRetryOrLevelRestart()
```

Демо ad unit для Rewarded: `demo-rewarded-yandex`. Заменить на настоящий только после тестов и модерации. Не кликать по live объявлениям при тестировании и не имитировать показы.

### Д. Согласие и privacy (обязательно проектировать заранее)

Яндекс сообщает, что consent для обработки персональных данных нужно передавать в SDK при каждом запуске; для пользователей GDPR-регионов обработка данных должна происходить только при наличии согласия. Реализовать понятный диалог/настройку отказа и передачу значения через API текущей версии (`setUserConsent` на соответствующих нативных интеграциях; для Unity сверить соответствующий SDK 8 API/sample). Согласие должно быть реальным и добровольным; нельзя считать молчание согласием без правового основания. Потребуется privacy policy и точное описание SDK/аналитики/data safety форм площадки. Yandex SDK интеграция включает AppMetrica; учесть это в раскрытии данных.

Перед обработкой данных в EEA/UK/США перепроверить требования к privacy, consent, детской аудитории и рекламному идентификатору. Отсутствие российского юрлица в ЕС не отменяет автоматически GDPR для обработки данных пользователей EEA.

### Е. Проверка интеграции

1. Установить тестовую development сборку на HONOR X8b; сначала проверить без подключения к сети, затем с сетью.
2. Использовать `demo-rewarded-yandex`; проверить success, no-fill/network error, закрытие без награды, получение награды, повторный показ, background/foreground и отсутствие двойной награды.
3. Windows PowerShell logcat:

```powershell
adb logcat | Select-String -Pattern "Yandex Ads"
```

Успешные сообщения SDK 8 включают `integrated successfully` и `initialized successfully`; сравнить точные строки с актуальным quick start.

4. Измерить время первого кадра, frame-time peaks, память и длительную сессию до/после SDK; сверить на X8b. Проверить сборку в Google Play internal testing и на других Android аппаратах.
5. Перед публикацией убедиться, что demo unit заменён, настоящий unit одобрен, consent и privacy policy работают, частота рекламы ограничена, кнопка закрытия корректна, выдача награды идемпотентна.

## Порядок первой Android публикации

1. Завершить игровой MVP без коммерческой зависимости; проверить на X8b и ещё одном Android устройстве, а также на разных разрешениях.
2. Сделать production-like Android App Bundle, подписать безопасным release key и сохранить резервную копию вне общего репозитория.
3. Подготовить package ID, название, описание, icon, screenshots, возрастной рейтинг, privacy policy, Data safety форму, рекламу declaration, тестовый аккаунт/инструкции для ревью.
4. Указать актуальный target API 36 для Google Play (по правилам с 31 августа 2026); пройти тестовую дорожку. Для личных аккаунтов, созданных после 13 ноября 2023 — closed test: 12 testers opt-in 14 дней подряд и подать запрос на production access.
5. Проверить crash/ANR, отзывчивость, рекламу/consent, data collection и подписанный AAB; только затем подавать production review.
6. Публиковать staged rollout, следить за crash reports/отзывами/retention/ad quality; остановить rollout, если появляются блокирующие ошибки.
