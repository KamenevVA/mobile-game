# Инструменты, Codex skills, экономия контекста и HONOR X8b

Дата проверки источников: 15 ноября 2026. Перед установкой сверяйте текущую версию и лицензию по ссылкам: сторонние репозитории меняются.

## Комплект скиллов: добавлять постепенно, не ставить всё подряд

Скилл — это инструкции/ресурсы агенту, не магическая модель и не гарантия правильного кода. Каждый установленный скилл имеет цену в контексте и потенциальные инструкции, которые надо просматривать.

| Область | Кандидат | Что проверить и как применять |
|---|---|---|
| Unity workflow, 2D, UI, performance, IAP | [Unity-Technologies/unity-agent-plugin](https://github.com/Unity-Technologies/unity-agent-plugin) — официальный Codex plugin Unity | Репозиторий содержит Codex plugin и skills для проекта, performance и монетизации. Лицензия `Unity Companion License`, не стандартная MIT/Apache: до установки прочитать лицензию и не предполагать, что можно свободно переупаковывать/распространять. Интеграция может быть beta; сверять актуальный Codex plugin manager и локальную версию. Не просить skill подключать IAP/LevelPlay, пока это не выбрано. |
| Универсальный геймдизайн/QA/art/audio | [gamedev-skills/awesome-gamedev-agent-skills](https://github.com/gamedev-skills/awesome-gamedev-agent-skills) | Каталог большой и молодой. Выбрать максимум нужные навыки (игровой loop, UI/UX, QA/performance, sound/art) после просмотра конкретных `SKILL.md` и каждой лицензии. Не устанавливать весь набор: он дублирует инструкции и расходует контекст. Не принимать число звёзд из обсуждений за показатель качества. |
| Экономия Codex | [otnc/skills_ai-agent-saving-tech](https://github.com/otnc/skills_ai-agent-saving-tech), MIT, skill `token-saver-codex` | Короткие правила поиска/чтения небольшими фрагментами, компактного вывода, настроек Codex и read-only audit script. Молодой проект с небольшой аудиторией; его проценты экономии — не доказательство. Проверить применимость каждой настройки к версии Codex. |
| Кодовая карта | [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify), пакет PyPI `graphifyy` | Локальный граф функций/классов/imports, query вместо повторного чтения файлов. Требует Python 3.10+ и устанавливает skill/настройки. Это карта кода, не история чата; генерируемый граф может быть устаревшим, его надо перестраивать после крупных правок. Лицензию и package metadata проверить до установки. |
| Контекст между сессиями | Проектный `PROJECT_STATE.md`, changelog и компактный `AGENTS.md` | Уже работает без дополнительной зависимости и хранится рядом с проектом. После задачи писать сделано/изменённые файлы/проверки/ошибки/точный следующий шаг. Не дублировать всю переписку в памяти. |
| ASO / публикация | [before-skills](https://github.com/alexszczurek/before-skills) (кандидат) | Указан как навык под App Store metadata. Применять на этапе листинга, проверив актуальность правил и лицензию; не использовать как источник юридических требований. Для Android ASO правила площадки проверять отдельно. |

### Что не ставить сейчас

- одновременно десятки навыков и MCP-серверов;
- агентские MCP мосты к Unity/Godot, пока нет реальной задачи, которую нельзя выполнить редактором/CLI;
- навыки с автоматическим деплоем, платежами или публикацией;
- малоизвестные навыки, которые требуют запускать скачанный скрипт без аудита;
- «память чата» с обещанием сбросить/обойти лимит. Карта проекта не стирает уже отправленную историю и не должна обещать обход квот.

## Пошаговая установка экономии контекста (Windows + Codex)

Устанавливайте в корне игрового репозитория после создания проекта, чтобы навыки были локальны проекту и передавались соучредителю. Текущий каталог пока не содержит игры. Команды ниже приведены для будущего PowerShell окна.

### 1. Перед установкой

1. Установить Node.js LTS с [nodejs.org](https://nodejs.org/) и Python 3.10+ с [python.org](https://www.python.org/downloads/windows/); для Graphify предпочтителен `uv` с официальной страницы [Astral uv](https://docs.astral.sh/uv/getting-started/installation/).
2. Проверить версии:

```powershell
node --version
npm --version
py --version
uv --version
```

3. Сделать Git commit или копию проекта. Сначала читать `SKILL.md`, скрипты и лицензию; не передавать ключи рекламных кабинетов/подписи AI агенту.

### 2. Установить один проектный token saver

В корне репозитория:

```powershell
npx skills add otnc/skills_ai-agent-saving-tech --skill token-saver-codex -a codex
```

**В этой рабочей папке навык уже установлен** в `.agents/skills/token-saver-codex` и просмотрен. Был запущен только его read-only audit script. Он сообщил: нет найденного project always-loaded instruction файла; `model_verbosity` не low; не задан `tool_output_token_limit`; включён 1 MCP server (`node_repl`); найдено 1 локально доступное skill плюс пользовательские. Скрипт не менял настройки. Его оценка токенов приблизительная. Низкая verbosity/лимит вывода — рекомендации, не изменения: глобальные настройки Codex не редактировались.

Проверить созданные файлы в `.agents/skills` (точный путь CLI может показать при установке) и содержание навыка до применения. Перезапустить Codex, открыть skill browser/написать `$token-saver-codex` или попросить Codex проверить список доступных skills. Если установка глобальная случайно выполнена, CLI имеет команду uninstall — сначала посмотреть `npx skills --help`, затем удалить только этот skill.

Скилл предлагает audit. Скрипт, указанный репозиторием, read-only; всё равно сначала открыть файл и убедиться, что он не пишет конфиги. Пример запуска из каталога установленного skill:

```powershell
node .agents/skills/token-saver-codex/scripts/audit.mjs --agent codex --json
```

Если путь отличается, найти его:

```powershell
Get-ChildItem .agents/skills -Recurse -Filter audit.mjs
```

Попросить Codex подготовить diff настроек и просмотреть его вручную; никаких параметров/файлов конфигурации применять автоматически без понимания, что они делают. Лимиты продукта зависят от плана и времени: сверять [официальную справку Codex usage limits](https://help.openai.com/en/articles/20001625-understanding-chatgpt-and-codex-usage-limits).

### 3. Установить Graphify только после появления исходников

В PowerShell из корня репозитория:

```powershell
uv tool install graphifyy
graphify --version
graphify install --project --platform codex
```

Для Python/PowerShell важно именно имя пакета `graphifyy` (две `y` в конце), команда `graphify`. Не пользоваться неопределённым bare `graphify install`: обнаружена неоднозначность выбора платформы; для Codex явно передавать `--platform codex`. Затем перезапустить Codex и проверить, что появился проектный `.agents/skills/graphify/SKILL.md` (либо путь, показанный установщиком).

Первичная индексация:

```powershell
graphify .
graphify query "Where is level progression loaded and saved?"
```

В Codex можно вызвать `$graphify` и попросить его собрать/обновить граф, затем задать конкретный вопрос. Для обновления после крупного изменения повторить `graphify .`; если версия поддерживает инкрементальный режим — сначала проверить `graphify --help`.

Для удаления сначала прочитать help текущей версии:

```powershell
graphify uninstall --help
```

После этого удалить проектную интеграцию командой, которую выдаёт help для `--project --platform codex`; затем удалить CLI:

```powershell
uv tool uninstall graphifyy
```

Перед удалением интеграции сделать diff: инсталлятор может менять `AGENTS.md` и `.codex` hooks; оставить собственные изменения и удалить только вставленный Graphify блок. Не удалять граф/индекс до понимания, где хранится кэш.

### 4. Обновление handoff после каждой задачи

В конце каждой работы просить Codex обновить `PROJECT_STATE.md` следующими полями:

```text
Дата и этап:
Что выполнено:
Файлы и изменения:
Что проверено (команды/устройство/результат):
Открытые проблемы и решения:
Следующий конкретный шаг:
Секреты не записывать.
```

Сохранять сам handoff компактным (примерно 1–2 страницы); подробные сведения и ссылки класть в отдельные тематические документы. В новой сессии начать с `PROJECT_STATE.md`, затем открыть только указанный документ/файл. Это переносит состояние работы, но не «обнуляет» лимит уже отправленных сообщений.

## Проверка экономии на одинаковой реальной задаче

Сейчас исходного проекта нет, поэтому нельзя честно заявить, что навыки уже сократили usage. Нельзя подменять тест рекламными процентами авторов. Выполнить протокол после появления вертикального среза:

1. Сделать копию Git commit, записать один реальный баг с воспроизводимыми шагами, например: «после Undo неправильная нить остаётся занята в буфере».
2. Одинаковая модель/режим, одинаковые инструкции, чистая новая сессия перед каждым прогоном. Сессия A: без Graphify/token skill; сессия B: оба установлены и активны. Менять только условие инструментов.
3. В обоих случаях требовать одинаковые критерии: найти причину, исправить минимально, назвать изменённые файлы, выполнить ту же проверку/сборку и описать остаточный риск. Не включать MCP/другие skills.
4. Записать в `AI_EFFICIENCY_BENCHMARK.md`: дата, модель/режим, входной контекст, число запросов, usage/лимит до и после по экрану Codex (если UI показывает), время, файлы прочитанные, правильность исправления, побочные регрессии.
5. Повторить минимум на трёх задачах разного типа: поиск связи между файлами, небольшой баг, изменение/проверка уровня. Чередовать порядок A/B либо делать на одном commit, чтобы обучение/порядок не давали ложное преимущество.
6. Считать качество обязательным: задача с меньшим расходом, но неверным результатом, не является улучшением. Если статистика usage не видна на выбранном плане, так и отметить; использовать число запросов и время только как прокси, не называть это токенами.

## ИИ workflow для начинающих

1. До кода вместе зафиксировать одну маленькую задачу и критерий готовности.
2. Попросить агента сначала показать короткий план и файлы, которые он намерен затронуть.
3. Изменять один вертикальный слой за раз: input → правило игры → feedback → сохранение → UI.
4. Просить объяснять незнакомые изменённые места простым языком; не принимать код, который никто из команды не может объяснить.
5. Запускать игру и проверять touch/layout на телефоне после каждой игровой функции. AI не видит реальный игровой feel без фактического запуска/видео/замеров.
6. Проверять diff, логи и тест на устройстве; только затем commit.
7. Запрашивать локальные правки, не «перепиши всю игру»; избегать передачи огромных каталогов `Library`, `Temp`, `obj`, `Build` и Android build output.

## План профилирования HONOR X8b

HONOR указывает для X8b экран 90 Гц, Snapdragon 680/Adreno 610 и 4500 mAh typical; конфигурации RAM/накопителя зависят от рынка. Узнать Android, RAM и свободное место на конкретном устройстве в Settings → About phone/Storage. Наша цель — стабильные 60 fps, то есть кадр укладывается примерно в 16.7 мс; 90 fps не цель релиза.

### Настройка тестового телефона

1. Включить Developer options и USB debugging; подключить USB, подтвердить RSA prompt на телефоне.
2. Проверить `adb devices` из Android SDK Platform Tools (идут с Unity Android Build Support либо устанавливаются отдельно с Android Studio).
3. Установить Development Build с profiler connection для измерений; финальную перепроверку делать также на release-like build без Editor overhead.
4. Зафиксировать модель/версию OS/память, яркость, battery %, режим обновления экрана, температуру комнаты и состояние сети; повторные тесты проводить сходно.

### Метрики и целевые сигналы

- кадр/CPU/GPU frame time: базовая цель — стабильно ниже 16.7 мс в gameplay; смотреть длинные пики, а не только среднее;
- отсутствие регулярных подвисаний на переходах, загрузке уровня, показе рекламы и открытии UI;
- Android memory/PSS не растёт бесконечно в 20-минутной сессии; нет crash/ANR и предупреждений о нехватке памяти;
- стартовый экран, загрузка первого уровня и возврат из рекламы — измерить секундомером/профайлером, записать baseline и регрессии;
- после 20 минут проверить заметный нагрев, throttling, drain батареи; сравнить одинаковый сценарий без рекламы и с тестовой рекламой.

### Инструменты и последовательность

1. Unity Profiler → Android device: CPU Usage, Rendering, Memory, UI, Audio; начать с Unity Profiler, не ставить сторонние performance SDK.
2. Android Studio Profiler / `adb logcat` — ошибки, память, падения, ANR; Yandex SDK интеграцию проверить строками `Yandex Ads`.
3. Снять профиль baseline на 10–15 минут: меню → 10 уровней → паузы/переходы → награда за тестовую рекламу → возврат.
4. При проблеме сначала найти дорогой кадр/аллокацию, затем изменить одну причину и повторить сценарий.
5. Проверить на реальном телефоне: несовпадение со статистикой Editor/эмулятора — ожидаемо; окончательное решение только по физическому аппарату.

### Практические настройки 2D

- фиксировать целевую частоту игры до 60, если 90 не даёт измеримого улучшения;
- держать спрайты и UI текстурами разумного размера, использовать атласы, компрессию платформы Android; проверить визуальные артефакты;
- избегать full-screen blur/частиц на весь экран, лишних Canvas rebuild, частого `Instantiate/Destroy` в активном цикле;
- не делать тяжёлые вычисления/поиск пути каждый кадр; обработка уровня — по событию касания/перехода;
- включить профилирование памяти, проверить сцену при смене уровня и возвращении приложения из background;
- рекламную библиотеку измерять отдельно: плагин и зависимости могут увеличить APK/AAB, память и время загрузки.
